# EventWall

Живая фотостена для мероприятий: свадеб, дней рождения, корпоративов, концертов.

Организатор создаёт событие и получает QR-код. Гости сканируют его телефоном и загружают фото
без регистрации, а снимки сразу появляются на общей стене, которую можно вывести на экран или проектор.

**Сайт:** https://ewentwall.vercel.app

## Возможности

- **Для организатора** — создание события в несколько шагов, QR-код и постер для печати или отправки,
  обложка, PIN-код на вход, премодерация фото, комментарии, реакции, скачивание фото гостями.
- **Для гостей** — вход по QR-ссылке без аккаунта, загрузка нескольких фото сразу, реакции и комментарии.
- **Живая стена** — новые фото появляются в реальном времени (Server-Sent Events).
- **Админка** — пользователи, события, жалобы и модерация, отзывы, тексты лендинга (RU/EN),
  настройки платформы, журнал действий.
- Вход по email и паролю или через Google, светлая и тёмная тема, русский и английский языки.

## Как устроено

```
Телефон / браузер
      │
      ▼
Vercel — frontend (Next.js)          frontend/
      │  REST API + SSE
      ▼
Render — backend (NestJS)            backend/
      │
      ▼
Supabase — PostgreSQL + хранилище фото
```

| Часть | Технологии | Подробности |
| --- | --- | --- |
| `frontend/` | Next.js (App Router), React, TypeScript, Tailwind CSS v4 | [frontend/README.md](frontend/README.md) |
| `backend/` | NestJS, TypeScript, Prisma, PostgreSQL, JWT, Google OAuth | [backend/README.md](backend/README.md) — API, авторизация, команды |
| Деплой | Supabase → Render → Vercel | [DEPLOY.md](DEPLOY.md) — пошагово |

QR-код события рисуется прямо в браузере из ссылки гостя (`/e/{slug}`), поэтому показывается сразу,
даже пока сервер просыпается.

## Запуск на своём компьютере

Нужен Node.js 24+.

```bash
# 1. Бэкенд — http://localhost:8000/api
cd backend
npm install
cp .env.example .env          # заполнить секреты, ADMIN_EMAIL и ADMIN_PASSWORD
npm run db:local              # локальная база PostgreSQL
npm run db:migrate:dev
npm run db:seed -- --demo     # админ + демо-данные
npm run start:dev
```

```bash
# 2. Фронтенд — http://localhost:3000 (в другом терминале)
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

С телефона в той же Wi-Fi сети сайт открывается по IP компьютера: `http://192.168.x.x:3000`.
Пока компьютер выключен или спит, локальная версия, конечно, не работает — для этого есть версия на Vercel.

> **Локальная база и база сайта — разные.** Аккаунты, созданные локально, на сайте не существуют:
> там нужно зарегистрироваться заново. Админ на сайте создаётся из `ADMIN_EMAIL` / `ADMIN_PASSWORD`
> в настройках Render (Environment) при первом запуске; позже пароль из переменной уже не перезаписывается.

## Обновление сайта

`git push` в ветку `main` — Vercel и Render сами пересоберут проект.

Бесплатный сервер Render засыпает после 15 минут без запросов, и первый запрос после этого идёт около минуты.
Чтобы этого не было, внешний монитор (UptimeRobot или cron-job.org) каждые 5 минут обращается к
`https://eventwall-api.onrender.com/api/health`. Заодно это не даёт бесплатному Supabase уйти на паузу.
Если сервер всё же уснул, сайт при открытии сразу отправляет фоновый запрос к `/api/health`
([WakeApi.tsx](frontend/src/components/WakeApi.tsx)), и сервер начинает просыпаться, пока посетитель читает страницу.
